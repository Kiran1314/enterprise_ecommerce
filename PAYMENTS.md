# Payment Gateway Configuration

Checkout accepts Cash on Delivery without a gateway. Administrators can configure the gateway and credentials in **Admin Console → Store & Currency Settings → Payment Gateway**. Supported providers are Stripe, Network International, Checkout.com, Razorpay, and PayPal Business. PayPal uses the Business account's REST API Key (Client ID) and Secret (Client Secret); select Sandbox while testing and Live only with production app credentials. Optional Sandbox buyer username/password fields are encrypted for administrator reference only; they are not used by the application to authorize API calls. `Automatic` selects an available provider for the selected region and falls back to configured PayPal credentials after the existing providers. Environment variables remain supported for deployments (`PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, and `PAYPAL_ENVIRONMENT`).

Provider adapters create hosted payment sessions so card or UPI details are never collected by this application. Set `NEXT_PUBLIC_SITE_URL` to the externally reachable storefront URL for provider return links. Razorpay payment links request UPI support. Credentials entered in admin settings are encrypted in MongoDB using `SETTINGS_ENCRYPTION_KEY`; set a stable, high-entropy value in production and keep it backed up. If it is not set, `SESSION_SECRET` is used. Losing or rotating the encryption key makes saved credentials unreadable.

For order emails, configure the SMTP host, port, TLS mode, username, password, sender address, and admin notification address in **Email Notifications**. The admin address defaults to the company support email. SMTP passwords are encrypted with the same settings key. Notifications are best-effort and do not prevent an order from being placed.

The order remains `Pending` until payment is confirmed. PayPal buyer approval is captured server-side and marked paid only after PayPal confirms the order reference, amount, and currency. Other providers still require payment verification and admin confirmation; configure and validate their webhook/callback verification before accepting production payments. Administrators can update payment and fulfillment state in order details; completing a COD order records it as paid. Customer and admin emails are sent after order placement. The customer success page shows the order details and a one-day delivery estimate.

The default super-admin credentials are intended only for initial access. Set a unique `SESSION_SECRET` and change the default password before deploying to production.
